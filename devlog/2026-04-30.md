## 追記: ADR-007 保存期間パージ運用方式の確定（2026-04-30）

### 目的

- `0001_init.sql` 着手前の最後の残ブロッカー（保存期間パージの実装方式）を解消する
- migration SQL の責務を「スキーマ定義のみ」に明確化する

### 採用方針

- **Cloudflare Workers Cron Triggers の `scheduled` ハンドラによる定期パージ**を MVP 仮採用
- migration SQL には DELETE 文を含めない（スキーマ責務のみ）
- ADR-005 で Workers ランタイムに確定済みのため追加インフラ不要
- 保持期間は Worker 側の環境変数 / 設定値で注入 → migration 変更不要で変更可能
- 将来クライアント別保持期間にも拡張容易

### 不採用にした方式

- 手動 `wrangler d1 execute`: 実行漏れ・誤実行リスク高、audit 残らない
- migration SQL での DELETE: 「migration は追加のみ」原則に反する、再適用で過去データ消失
- Cloudflare Queues 化: MVP では過剰、行数 / 要件が変わった時点で再評価

### 0001_init.sql に含めるもの / 含めないもの

含める:
- `docs/24 §6` の20テーブルの `CREATE TABLE`
- `docs/24 §9` の必須 index
- 外部キー制約（ブロック形式）

含めない:
- 実データ削除文（`DELETE FROM ...`）
- 保持期間値そのもの（マジックナンバー禁止）
- パージ実装コード / Cron 設定 / wrangler 設定
- `PRAGMA foreign_keys = ON;` の永続化（接続側責務）

### 保持期間の仮方針（MVP）

```txt
audit_logs:                       180日
sync_job_logs:                    90日
sync_job_logs (log_level=error):  180日
csv_import_jobs:                  90日
csv_import_rows:                  90日
menu_item_versions:               無期限
dom_snapshots / dom_diffs:        Phase 2 で導入時に適用（90/180日）
screenshots / execution artifacts: 90日（Phase 2）
```
